# Video synchronization and sensory energy

These scripts prepare the motion and acoustic measurements used by the repository-root [sensory_inputs.py](../../sensory_inputs.py) for Fig. S11–S12. Motion energy comes from synchronized camera video; acoustic energy comes directly from the NSP-2 microphone recording. The two measurements are extracted separately and are combined with neural activity in the analysis script.

The [processing record](README_process_motion.md) describes the original choices, available outputs, and limits of the retained provenance. Raw patient video and NS5/NEV recordings are not included in this folder; rerunning extraction requires access to those source files.

## Workflow

```text
sessions.csv ── generate_video_sync_configs.sh ── configs/*.yaml
                                                     │
camera MP4 + frame JSON + NSP NEV/NS5 ── run_video_sync_configs.sh
                                                     │
                                             synchronized video
                                                     │
                                           get_motion_energy.sh
                                                     │
                                    energy/*_motion_energy.csv

sessions.csv ── update_ns5_path.py ── sessions_ns5path.csv
                                              │
NSP-2 microphone + bin_times/*.npy ── get_acoustic_energy.py
                                              │
                         energy/*_RoomMic1_acoustic_energy.npy
```

| Script or folder | Purpose |
| --- | --- |
| `update_ns5_path.py` | Find one NSP-2 recording per session and write its path to a CSV. |
| `generate_video_sync_configs.sh` | Write one synchronization configuration per eligible session. |
| `run_video_sync_configs.sh` | Run the local `video-sync/` implementation for each configuration. |
| `get_motion_energy.sh` | Extract full-frame motion magnitude from available synchronized videos. |
| `get_acoustic_energy.py` | Calculate microphone RMS in the saved neural bins. |
| `video-sync/` | Synchronization implementation, dependencies, and upstream documentation; see its [license](video-sync/LICENSE). |
| `motion-energy/video_motion_analysis.py` | Optical-flow calculation and optional plotting. |
| `configs/`, `sessions*.csv` | Session selection and recording locations used for processing. |
| `bin_times/` | Neural bin start times in milliseconds; required input, not generated by these scripts. |
| `energy/`, `videos/` | Energy outputs and video-processing records. The retained `videos/` folder contains metadata and missing-video markers, without the actual videos. |

## Processing settings

| Measurement | Settings used |
| --- | --- |
| Camera | `18486638` (B1), selected as the full-body view in the original processing notes. |
| Synchronization | Match NEV chunk serials to camera frame metadata; extract the corresponding video sections and concatenate them. The local FFmpeg command writes constant 30 fps video. |
| Audio attached to video | `RoomMic2`, exported at 30 kHz by the synchronization code. |
| Motion | Grayscale, whole frame, dense Farneback flow; sum the vector magnitudes over all pixels. No bounding box is passed by the batch script. |
| Farneback parameters | `pyr_scale=0.5`, `levels=3`, `winsize=15`, `iterations=3`, `poly_n=5`, `poly_sigma=1.2`, `flags=0`. |
| Acoustic | `RoomMic1` from NSP-2, scaled to microvolts; subtract each bin's mean, then compute `sqrt(mean(signal**2))`. These are microphone RMS amplitudes, not calibrated sound-pressure measurements. |
| Neural bins | 100 ms. All 29 retained bin-time arrays are one-dimensional, begin at zero, and have consecutive 100 ms starts. |

Motion CSVs contain one column **without a header**, including zero for the first frame, which has no preceding frame. Acoustic NPY arrays contain one value for each supplied neural bin start, covering `[start, start + 100 ms)`. The motion plotting helper masks values above `0.4e6` for display only; this does not alter the saved CSV, and batch extraction disables plotting.

## Running the scripts

The examples start in this folder:

```bash
cd scripts/sensory_inputs
```

The batch scripts resolve their default input/output folders relative to their own locations. Absolute paths in existing YAML and CSV files still refer to the original recording server. The scripts write files, so use a separate output directory when preparing a new run alongside the retained results.

### 1. Locate recordings and create configurations

`update_ns5_path.py` requires pandas. Its original recording root is `/home/hungyun/wrangell/stitched/EMU-18112`; set `EMU_SOURCE_ROOT` if the recordings are mounted elsewhere. Both this script and the configuration generator exclude `YEX` and `YEW`. The reason for those exclusions is not recorded in the retained notes.

```bash
python update_ns5_path.py
bash generate_video_sync_configs.sh --dry-run
bash generate_video_sync_configs.sh
```

The first command writes `sessions_ns5path.csv`, retaining rows with missing or ambiguous recording matches as empty paths. It checks that the recording root exists before replacing the path table. The configuration generator reads `sessions.csv` directly and skips existing YAML files. Use `--force` only when intentionally replacing configurations.

| Environment variable | Used by | Purpose |
| --- | --- | --- |
| `SESSIONS_CSV` | Path finder, config generator | Source session table. |
| `EMU_SOURCE_ROOT` | Path finder, config generator | Stitched NSP root. The generator defaults to `$HOME/wrangell/stitched/EMU-18112`. |
| `NS5_PATHS_CSV` | Path finder, acoustic batch | Output/input path table; defaults to this folder's `sessions_ns5path.csv`. |
| `CAMERA_SOURCE_ROOT` | Config generator | Camera root; defaults to `$HOME/wrangell/datalake/emu`. |
| `VIDEO_OUTPUT_ROOT` | Config generator, motion batch | Video output/input root. The generator defaults to `$HOME/wrangell/hungyunlu/videos`; motion extraction defaults to this folder's `videos/`. |
| `CONFIG_OUTPUT_DIR` / `CONFIG_DIR` | Config generator / video runner | Configuration output/input folder; both default to `configs/`. |
| `BIN_TIMES_DIR` | Acoustic batch | Neural bin-time folder; defaults to `bin_times/`. |
| `ENERGY_DIR` | Motion and acoustic batches | Energy output folder; defaults to `energy/`. |

Set `VIDEO_OUTPUT_ROOT` consistently when generating configurations and extracting motion. Existing YAML files retain their recorded output paths until regenerated; setting the variable for the runner does not override a YAML file. For example, to generate a separate configuration set targeting the local video folder:

```bash
export VIDEO_OUTPUT_ROOT="$PWD/videos"
export CONFIG_OUTPUT_DIR="$PWD/configs_local"
export CONFIG_DIR="$CONFIG_OUTPUT_DIR"
bash generate_video_sync_configs.sh --dry-run
bash generate_video_sync_configs.sh
```

### 2. Synchronize and stitch video

Use the environment specified in [video-sync/environment.yml](video-sync/environment.yml), plus FFmpeg on `PATH`. That environment specifies Python 3.12 and includes a Git/SSH dependency on the lab's Blackrock utilities. The batch uses this local copy of `video-sync`, which contains session-handling changes; replacing it with a fresh upstream checkout need not reproduce the same behavior.

```bash
conda activate videosync
bash run_video_sync_configs.sh --dry-run
bash run_video_sync_configs.sh
```

The runner calls `python -m pyvideosync.main --config <absolute-config-path>` from `video-sync/`. `PYTHON_BIN` can select another interpreter and `VIDEO_SYNC_DIR` another implementation. By default it attempts every configuration and returns a nonzero exit code if a command fails; `--stop-on-error` stops at the first failure. A completed command can still produce a `no_corresponding_videos.txt` marker instead of a video, so inspect the outputs as well as the batch status.

Multiple matched clips produce `<session>/18486638/stitched_18486638.mp4`. With just one clip, the current synchronization implementation keeps its generated `*_final_*.mp4` name. In that case, use the exact final path reported by synchronization to create the expected `stitched_18486638.mp4` filename before running the motion batch; do not choose an arbitrary intermediate clip.

### 3. Extract motion energy

The motion batch uses `uv` with this folder's `pyproject.toml` and `uv.lock`. It defaults to `$HOME/.venvs/motion-energy` for the environment and `UV_LINK_MODE=copy`; both can be overridden. This environment covers OpenCV motion extraction, not video synchronization or Blackrock audio reading.

```bash
bash get_motion_energy.sh --dry-run
bash get_motion_energy.sh
```

The batch processes `VIDEO_OUTPUT_ROOT/<session>/18486638/stitched_18486638.mp4` and writes `ENERGY_DIR/<session>_motion_energy.csv`. Existing CSVs are retained, missing videos are reported and skipped, and extraction failures are counted and produce a nonzero exit code. The original explicit skip of `YFB_0044_pursuit` is retained; its saved motion CSV is already present.

A single-video equivalent, using the same full-frame Farneback settings, is:

```bash
uv run --project . python motion-energy/video_motion_analysis.py \
    /path/to/stitched_18486638.mp4 \
    --method farneback --save-data /path/to/session_motion_energy.csv --no-plot
```

The extractor loads an existing `--save-data` file instead of recalculating it. Use a new destination when a recalculation is intended. For optional background execution, save stdout and stderr to new log names, for example `nohup bash get_motion_energy.sh > motion_run.log 2> motion_run_errors.log &`; these are suggested commands, not a recovered terminal history.

### 4. Extract acoustic energy

Use a Python environment with NumPy, pandas, SpikeInterface, and its Neo/Blackrock-reading dependencies. The original acoustic environment was not recorded here. The root analysis environment's [requirements.txt](../../requirements.txt) includes these Python dependencies; the motion-only `uv` environment does not.

```bash
python get_acoustic_energy.py
```

The batch reads `sessions_ns5path.csv`, requires exactly one bin-time file per patient/EMU recording, and uses the explicit `BIN_SIZE_MS = 100` and `AUDIO_CHANNEL = 'RoomMic1'` settings. Existing arrays are retained. Sessions without recording paths are skipped; missing/ambiguous bin files, incompatible bin spacing, or processing failures are reported and produce a nonzero exit code after the other sessions are attempted. Output task names are lowercase to match the analysis inputs.

`get_rms_at_bin_times()` is the calculation used by this batch. The other audio helpers support optional waveform or full-session-envelope inspection. The RMS calculation is also present in the repository-root `data_loader.py`; the preprocessing copy can run independently of the analysis imports.

## Using the outputs in the analysis

The root analysis reads the following locations through `utils.read_energy_files()`:

| Extraction output | Analysis input |
| --- | --- |
| `energy/<session>_motion_energy.csv` | `data/sensory_inputs/motion-energy/<session>_motion_energy.csv` |
| `energy/<session>_RoomMic1_acoustic_energy.npy` | `data/sensory_inputs/acoustic-energy/<session>_RoomMic1_acoustic_energy.npy` |

Placing outputs in those analysis folders is a separate transfer step; these scripts do not copy them automatically. The 12 motion CSVs and 19 acoustic arrays retained here are byte-for-byte identical to their counterparts in those folders. Each acoustic array has the same shape as its corresponding bin-time array.

The current analysis reader averages motion values in groups corresponding to 30 fps (three frames per 100 ms), then pads missing tail values with NaNs or truncates excess values to the neural-array length. It uses `pd.read_csv()` without `header=None`, so it currently consumes the first motion value as a column header. That behavior and the correspondence between stitched-video frame zero and neural time zero need to be checked before a new sensory-control rerun. The saved CSVs do not themselves carry timestamps, and length matching alone does not verify temporal alignment. This preprocessing documentation does not change the analysis reader or recompute existing figure results.
